## Why — 目指す価値

人間とAIが、それぞれに適した方法で、複雑な作業を自然に協調して進められるようにする。

最近のAI開発ツールは「Agentに大量のToolを渡す・並列実行する・コンテキストを最適化する」方向、すなわちAIの実行効率の最大化を重視する。しかし、AIが多くの作業をこなせることと、人間がその作業を理解・管理しやすいことは別問題である。むしろAgentが増えるほど、人間側の認知負荷は増えかねない。

## What — Plugumiが提供するもの

ツール・AI・人間の間で、操作・状態・情報・UIを連携させるための、**拡張可能な共通プロトコルと実行基盤**。

Plugumi自身はAI Coding AgentでもIDEでもない。そういうものを自由に組み立て、協調させるための基盤である。「快適なAI駆動開発環境」はPlugumiを使って実現したい最終価値であり、最も重要な動機・最初のユースケースだが、プラットフォーム自体の役割とは区別する。

この定義なら、AIを使わないPlugin同士の連携や日常的なツールの統合も自然に対象になる。AIへの特化を避けながら、AIとの協働を最優先に設計できる。

### 3つの共通契約

| 契約 | 内容 |
|---|---|
| Communication Protocol | Tool呼出・実行状態・通知などをツール間で扱う共通の仕組み |
| UI Protocol | Panel、Embed、表示・操作の連携を通して人間がPluginの機能や結果を利用できる仕組み。特定のフロントエンド技術に依存しない |
| Shared Context / Resource Model | 何を対象に操作しているか、どの実行・作業に関係するかをPlugin間で参照できる仕組み（独立プロトコル化は未定・共有範囲と所有権は今後の設計事項） |

単にメッセージを配送するだけでは協調作業として成立しない。例えば、AIがファイルを編集したとき人間側で対応するファイルや差分を開け、人間が操作した内容をAIが構造化された情報として受け取れる関係を作りたい。

ただし、人間とAIが同じJSONや同じUIを理解する必要はない。**共通の意味を持つ操作・情報に、それぞれに適した方法でアクセスできる**ことが本質である。

### プロトコル統一は手段であり目的ではない

優れた通信プロトコルが完成しても、人間が作業状況を理解・制御できなければPlugumiとしては失敗である。成功の判定軸はあくまで人間が複雑な作業を把握・制御できることに置く。

## 設計原則

| 原則 | 意味 |
|---|---|
| Human-first | AIの都合より、人間の理解しやすさと操作性を優先する |
| Observability | 何が起きているか・起きたかを必要な粒度で把握できる |
| Progressive Disclosure | 普段は重要な情報だけを表示し、必要なときに詳細へ掘り下げられる |
| Context Preservation | 作業の中断・再開・プロジェクト切替で、状況を思い出す負担を減らす |
| Composability | 必要な機能を自由に追加・連携し、自分に合った環境へ育てられる |
| Human–AI Parity | AI専用の操作体系に偏らず、人間も同じ環境の機能を自然に使える |

### Observability × Progressive Disclosure

この2つはセットで考える。例えば10個のAgentが並列で動いているとき、すべてのTool Callやログを常時表示すれば、情報量が多すぎて逆に把握しづらくなる。

```text
Project A — 開発状況
  6 実行中   2 確認待ち   3 完了

  認証機能の実装      実行中
  DBスキーマの変更    承認待ち
  テストの追加        完了
  （各作業を開くと、Agentの操作履歴・変更ファイル・Tool Callなどの詳細を確認できる）
```

重要なのはログを大量に表示することではなく、**今どこに注意を向けるべきかを判断しやすくすること**である。

Queueや通知の仕組みも同じ文脈で位置づく — AIの無駄な待機を削減するだけでなく、人間が待機状況や実行の進行を追いやすくするための仕組みである。

### 認知負荷を下げることは、すべてを単純化することではない

高機能なツールを使いたい人にとって、機能を隠しすぎたり操作を自動化しすぎたりすることもストレスになる。必要なときに必要な情報と操作へ素早く到達でき、自分で制御できることが大切。複雑な作業を人間が無理なく扱える環境を目指す。

## 範囲

- 対象: 共通プロトコルと実行基盤 — Core、Plugin機構、UI連携、協調の見せ方
- 利用者の作業領域: ソフトウェア開発を中心としつつ、日常的な作業にも拡張できる
- 対象外: Agent・Editor・Terminal等のアプリケーション機能そのもの（Pluginの責務）

## 成功シグナル

- 並列する作業・Agentの状況を一目で把握し、注意を向けるべき箇所を判断できる
- 人間とAIが同じ環境の機能を自然に使える
- 作業の中断・再開・切替で状況を思い出す負担が小さい
- AIを使わないPlugin同士の連携・日常ツールの統合が不自然なく成立する

## プロジェクトとしての成功条件

個人開発としての「自分が作っていてワクワクすること」も失わない。これは利用者向けの要件とは別に、プロジェクトを続けるための大事な成功条件である。
